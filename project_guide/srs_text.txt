1. Introduction 
This document defines the complete end-to-end requirements for an AI-powered job portal where 
job seekers and companies interact on a single platform. The system supports resume building, 
AI-based resume analysis, mock interviews, job recommendations, hiring workflows, interview 
scheduling, feedback management, billing, and admin control. 
The platform is designed to help: 
 Candidates create strong resumes and improve interview performance. 
 Companies find better candidates faster. 
 Admins manage jobs, users, reports, and platform settings. 
 Super Admins track revenue and overall platform activity. 
 
2. User Types 
2.1 Job Seeker / Candidate 
The candidate is the person searching for jobs and applying for roles. The candidate can: 
 Register and login. 
 Complete resume details. 
 Edit resume at any time. 
 Run AI-based resume analysis. 
 Practice mock interviews. 
 Take official mock interviews. 
 View recommended jobs. 

 Apply for jobs. 
 Attend interviews. 
 View offer, rejection, or feedback. 
2.2 Employer / Company / Hiring Manager 
The company user manages recruitment activities. The company can: 
 Register as a company. 
 Activate Hiring Mode. 
 Create company profile. 
 Post jobs. 
 Review applications. 
 Shortlist candidates. 
 Schedule interviews. 
 Send interview feedback. 
 Update interview status. 
2.3 Admin 
The admin manages platform operations. The admin can: 
 Manage users. 
 Manage jobs. 
 Add jobs manually. 
 Import jobs in bulk using CSV. 
 View analytics and reports. 
 Manage platform settings. 
2.4 Super Admin 
The Super Admin has full platform-level access. The Super Admin can: 
 View all users, companies, jobs, and payments. 
 Track revenue. 
 Monitor premium subscriptions. 
 View detailed analytics. 
 Control advanced system settings. 
 
3. Login and Registration 
3.1 Registration 

A new user can register using: 
 Email 
 Mobile number 
 Password 
 Role selection such as Candidate, Company, or Admin 
After registration: 
 OTP verification is sent to email. 
 The account is created after verification. 
 The user is redirected to the proper dashboard based on role. 
3.2 Login 
A registered user can login using: 
 Email and password 
 Continue with Google 
3.3 First Login Redirect 
After successful login, the system redirects the user to: 
 Candidate Dashboard 
 Company Dashboard 
 Admin Dashboard 
 Super Admin Dashboard 
3.4 Security 
 Passwords are encrypted before storage. 
 OTP is required for verification and password recovery. 
 Login sessions are protected. 
 Failed login attempts are limited. 
 
4. Candidate Dashboard and Resume Flow 
4.1 Candidate Dashboard 
When a candidate logs in, the dashboard displays: 
 Resume completion status 
 AI analysis score 
 Mock interview section 
 Recommended jobs 

 Application status 
 Notifications 
If the resume is incomplete, the dashboard shows a Complete Resume card. 
4.2 Resume Builder 
The resume builder works in 7 steps. 
Step 1: Personal Information 
The candidate enters: 
 Full name 
 Email 
 Mobile number 
 Location 
Step 2: Education 
The candidate enters: 
 Degree 
 College or university 
 Passing year 
 Marks or CGPA 
Step 3: Work Experience 
The candidate enters: 
 Company name 
 Role 
 Duration 
 Short bullet points about work 
Step 4: Skills 
The candidate enters: 
 Technical skills 
 Soft skills 
 Languages 
Step 5: Projects 
The candidate enters: 
 Project name 
 Duration 

 Tech stack 
 Short description 
Step 6: Template Style 
The candidate selects: 
 ATS-friendly style 
 Modern style 
 Simple style 
Step 7: Preview and Download 
The candidate can: 
 Preview the resume 
 Edit the content 
 Download the resume as PDF 
4.3 AI Resume Analysis 
After the resume is completed or uploaded, the system performs AI-based analysis. 
The analysis includes: 
 ATS compatibility score from 0 to 100 
 Keyword match analysis 
 Gap analysis 
 Formatting check 
 Weak bullet point suggestions 
 Stronger content recommendations 
The system highlights: 
 Missing keywords 
 Missing sections 
 Weak experience descriptions 
 Better wording for bullets 
4.4 Resume Re-Analysis 
If the candidate edits the resume: 
 The system allows re-analysis. 
 The ATS score is updated. 
 Keyword matching is updated. 
 New suggestions are generated. 

4.5 Resume Limits 
 Free users can analyze the resume 3 times per month. 
 Premium users can analyze the resume unlimited times. 
 
5. AI Mock Interview 
5.1 Access Condition 
The AI Mock Interview section appears only after the resume is complete. 
5.2 Practice Mode 
Practice mode is for learning and preparation. 
Features: 
 Unlimited practice 
 No final score saved 
 Resume-based questions 
 Technical questions 
 Behavioral questions 
 Instant feedback 
5.3 Official Mode 
Official mode is the scored version. 
Features: 
 Final score is saved 
 Confidence level is shown 
 Used for recommendations 
 Used for candidate progress tracking 
5.4 Question Categories 
The AI can ask: 
 Resume questions 
 Project questions 
 Technical questions 
 Behavioral questions 
 Experience questions 
 
6. Job Recommendations 

6.1 Recommendation Logic 
After the candidate completes the official mock interview, the system shows recommended jobs. 
The recommendation is based on: 
 Resume match score 
 Mock interview score 
 Skill match 
 Company rating 
 Company response speed 
6.2 Job Card Details 
Each job card shows: 
 Company name 
 Company rating 
 Job title 
 Salary 
 Location 
 Job type 
 Match percentage 
6.3 Apply to Job 
The candidate can click Apply to send the application. 
When the candidate applies: 
 Resume is attached automatically. 
 Application is saved. 
 Company receives notification. 
 Candidate sees applied status. 
 
7. Company Dashboard and Hiring Mode 
7.1 Company Dashboard 
The company dashboard displays: 
 Company profile 
 Job listings 
 Applications 
 Interview schedule 

 Feedback section 
 Rating information 
7.2 Hiring Mode 
The company activates Hiring Mode by entering:

 Industry

 Description

The company can post jobs by entering: 
 Job title 
 Description 
 Required skills 
 Experience level 
 Salary range 
 Location 
 Job type

If the company provides only the job title: 
 The system can generate the job description automatically. 
 The AI can suggest required skills and experience. 
7.5 Applications Tab 
The applications tab shows: 
 Candidate name 
 Resume 

 ATS score 
 Mock interview score 
 Application status 
 Interview progress 
Applications can be filtered by: 
 Status 
 Score 
 Experience 
 Match percentage 
 
8. Application Flow and Notifications 
8.1 Application Process 
When a candidate applies: 
 The application is stored in the database. 
 The company receives a notification. 
 The candidate gets confirmation. 
8.2 Notification Methods 
The system sends notifications through: 
 Dashboard notification 
 Email notification 
 Push notification if enabled 
8.3 Notification Content 
The notification includes: 
 Candidate name 
 Job title 
 Resume link 
 ATS score 
 Confidence level 
 Date and time of application 
 
9. Interview Scheduling 
9.1 Schedule Interview 

When a company shortlists a candidate: 
 The company can schedule an interview. 
 The company selects date and time. 
 The company selects interview mode. 
9.2 Interview Modes 
The interview can be: 
 In-person 
 Google Meet 
 Zoom 
9.3 Meeting Link 
If the interview is online: 
 The system auto-generates a meeting link. 
 The candidate receives the meeting link. 
 The candidate receives interview details. 
9.4 Candidate View 
The candidate can see: 
 Interview date 
 Interview time 
 Interview mode 
 Company name 
 Job title 
 Meeting link 
 Preparation tips 
 
10. Interview Decision and Feedback 
10.1 Interview Status 
After the interview, the employer selects one of these statuses: 
 Approved 
 Rejected 
 In Progress 
10.2 Approved 
If approved: 

 Offer details are shown. 
 Salary 
 Joining date 
 Documents required 
 Candidate can accept or reject the offer 
10.3 Rejected 
If rejected: 
 The company fills rejection reasons. 
 Optional comments can be added. 
 AI converts the feedback into professional wording. 
 Candidate receives the feedback. 
10.4 In Progress 
If more rounds are needed: 
 The status becomes In Progress. 
 Next round details are shown. 
 Candidate gets preparation tips. 
 
11. Company Rating and Response Incentive 
11.1 Rating System 
Each company has a public rating based on: 
 Response speed 
 Interview scheduling consistency 
 Candidate feedback 
11.2 Purpose 
 High-rated companies are shown more prominently. 
 Low-rated companies are shown lower. 
 This encourages companies to respond quickly. 
11.3 Badge System 
The platform may show: 
 Star rating 
 Active hiring badge 
 Slow response warning 

 High response badge

 Salary

14. Bulk Job Posting Using CSV 
14.1 CSV Upload Flow 
The admin can upload many jobs at once using CSV. 
14.2 Steps 
1. Download sample CSV template. 
2. Fill job data. 
3. Upload the file. 
4. System validates each row. 
5. System shows valid and invalid rows. 
6. Admin confirms import. 
7. Valid jobs are inserted into the system. 
14.3 Use Case 
This feature is useful for: 
 Campus placements 
 Internships 
 Government jobs 
 Bulk hiring campaigns

 Mock interview: Demo only 
 AI suggestions: Basic 
 Job alerts: Not available 
 Portfolio analyzer: Not available 
15.2 Premium Plan 
The Premium plan includes: 
 Unlimited resume analysis 
 Unlimited job search 
 Full mock interview access 
 Advanced AI suggestions 
 Daily job alerts 
 Daily email reports 
 Portfolio analyzer

17.1 Security 
 Passwords must be encrypted. 
 OTP must be used for verification. 
 Role-based access must be enforced. 
 Login sessions must be secure. 
17.2 Performance 
 The system should handle many users at the same time. 
 Pages should load fast. 
 AI analysis should respond quickly. 
17.3 Usability 
 The platform should be responsive. 
 Buttons and labels should be clear. 

 The user flow should be simple. 
17.4 Data Privacy 
 Users should be able to view their personal data. 
 Users should be able to delete their personal data. 
 Sensitive data should be stored safely.
